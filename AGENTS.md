# Team Agent

- Use English for development, agent communication, identifiers, comments and repository documentation. Preserve proper names and language-sensitive fixtures; localize only when requested.
- Use LF line endings for all maintained text, including source, documentation, active research evidence, caches and generated outputs. Configure writers explicitly; never rely on platform newline defaults. Retain original bytes before normalizing evidence and record the original and LF hashes in the migration manifest. Immutable originals are narrowly exempt only when their recorded hash verifies; do not normalize source checkouts, dependencies, binary/media or explicit byte fixtures. Register new owned cache/output roots with the LF gate.
- Before implementation read `spec/architecture/stack.md`, `spec/architecture.md`, the applicable platform specification and the active work in `spec/roadmap.md`. Adopted choices are requirements; planned applications are not evidence of implemented behavior.
- Read applicable installed `.agents/skills/*/SKILL.md` guides and their needed references before related work; use `spec/skills-audit.md` for scope and compatibility caveats. Skills do not select dependencies or frameworks merely by being installed. Verify examples against pinned package source when APIs differ, and resolve stale machine-specific reference links to their colocated files. The LogTape `release` skill is not this project's release procedure; Oxc's Rust performance skill does not apply to our TypeScript plugin. Use `entire-search` for relevant historical queries only.
- Aube owns JavaScript dependencies and the pinned `aube-lock.yaml`. Use `aube install --frozen-lockfile` for reproducible setup. Bun 1.4.2 runs JavaScript/TypeScript tasks, tests and tool launchers; either Aube or Bun may dispatch scripts. Do not introduce npm/pnpm/Bun dependency mutations, a second JavaScript lockfile, Node launchers or tsx. The desktop's native Rust dependencies use the checked-in Cargo.lock and locked Cargo builds.
- Use strict TypeScript 7 native preview with all flags in `tsconfig.json`. Before writing Effect code read **all** of `node_modules/effect/AGENTS.md`, then its relevant linked guides and installed RC source. Our shared CLI contract uses Cleye and C12; keep that decision even when a dependency guide illustrates another CLI framework.
- Libraries belong in `lib/`, application/runtime adapters in `app/`, generated assets in `data/`. Cross-library imports use `@/<library>` public entry points. Keep portable domain code free of Node/Bun APIs, DOM, app imports and generation tools. `lib/lint` is explicitly host-only development tooling.
- Every module exports its public API from `index.ts` and explicitly re-exports its literal `cli.ts` descriptor. Register dependencies in the acyclic module manifest; implement every advertised CLI command. Follow `spec/architecture/modules.md` and the implemented contract in `spec/harness.md`. CLI, web and desktop are the active surfaces; mobile implementation is deferred.
- Public fallible domain operations return typed Effects. Use services/layers for I/O, clocks and resource ownership, and scoped cancellation/cleanup. Execute Effects and configure loggers only at host boundaries. Pure computations stay pure. Libraries use LogTape; developer CLI tools use Consola. Tiny verification/logging protocol adapters may use process streams for machine-readable output.
- External JSON, configuration, files, worker/IPC/network messages and third-party dynamic values enter as `unknown`, pass Effect Schema, then semantic validation. Never use `any`, unsafe casts, non-null assertions, unchecked decoding or broad lint suppressions to bypass a boundary. Narrow third-party adapters need documented evidence and tests.
- Validate paths, containment, sizes, hashes, versions and coverage before using data. Bound queues, concurrency, caches, retries and timeouts. Report partial/missing/unsupported results explicitly; never silently drop work or substitute a source. Retain provenance and distinguish measured results from assumptions.
- Keep authorization and deterministic execution separate from model output. Follow `spec/security.md`. Never log secrets, credentials, private query values or raw tool payloads. Store sensitive app state outside public URLs; validate every transport boundary.
- Never use `eval` or the Function constructor to execute input. Dynamic executable loading belongs only in explicitly trusted host adapters; executable configuration is trusted local code, not a safe untrusted-data format.
- Shared app state is portable, heavy UI work runs in workers, and platform/storage capabilities stay in adapters. Follow `spec/architecture/applications.md` and `spec/architecture/mobile.md`. Verify real workerd/browser/native behavior for affected integrations; a successful web bundle is not a packaged native test.
- After each completed implementation step run `aube run --no-install step:check`; before review/delivery run `aube run --no-install review:check`. Fix failures before advancing and report any environment limitation explicitly. The repository descriptors in `.agents/hooks` are mandatory workflow instructions, not universal product hook APIs.
- Changes to web/native behavior also run the applicable `test:web`/`test:desktop` acceptance command. Keep normal gates credential-free; test the real Pi loop with deterministic provider fixtures and identify live-provider tests separately. Never equate normal agent completion with independently verified task correctness.
- Add regression coverage for behavioral defects and focused, fixture-tested lint rules for recurring structural failures. Do not weaken strictness, skip checks or update expected results solely to obtain a passing gate. Preserve original benchmark provenance, record actual runtime versions and separate cold/warm measurements.
- Preserve unrelated user changes and research/source evidence. No publishing, dependency trust-policy relaxation or data-source substitution without an explicit task requirement.
- Archive completed public responses via `.codex/hooks.json` and `spec/conversation-logging.md`, including user prompts and visible progress, never private reasoning or raw tool output. Until product hooks are trusted/observed, run the JSON writer immediately before the exact final response. Use global increasing record numbers and archive-relative links; preserve previous records. Apply explicit redactions when requested and label redacted content honestly.

Verification and hook operation: `spec/verification.md`.
