## Initial scoped source review — 2026-11-01

Reviewed commit `c0881ac7fe9d78623bc222f8ee93e2c722f5413b` (2026-10-30T13:22:04+08:00), its complete tree inventory and selected full OCR client, overlapped pipeline, Jev scorer/self-check and robustness/scheduling test bodies. The portable inventory ID retains its existing spelling; upstream names the project MiniCPM-OCR. This review does not execute model weights, servers, source tests or quality/performance benchmarks.

The Jev scorer compares the source image, rendered candidate and extracted text. It distinguishes two logits from already-normalized probabilities and leaves acceptance thresholds to callers. Stable softmax avoids overflow for ordinary finite logits, but the logits path lacks a finite-value check; NaN/infinite values can defeat probability semantics. `score_many` eagerly gathers every request and image-file construction reads whole files, so backend concurrency is not end-to-end admission control. Normalized scores are not calibrated correctness probabilities or permission decisions. [Scorer](https://github.com/openbmb/minicpm-ocr/blob/c0881ac7fe9d78623bc222f8ee93e2c722f5413b/scripts/minicpm-ocr-jev/sdk/jev_score/scorer.py).

The self-check inspects request shape, prompt fingerprint, last-token expectations and optionally local tokenizer equivalence. Missing weights/tokenizer dependencies skip token comparison while permitting overall `passed`; unknown/server-template prompt sources can also skip prompt inspection. Preserve each checked, failed and unchecked facet with model/renderer/tokenizer fingerprints instead of treating that Boolean as full model validation. Shape checks alone do not prove finite scores, correct server behavior or OCR quality. [Self-check](https://github.com/openbmb/minicpm-ocr/blob/c0881ac7fe9d78623bc222f8ee93e2c722f5413b/scripts/minicpm-ocr-jev/sdk/jev_score/selfcheck.py).

The OCR HTTP client randomizes endpoints, retries broad exceptions and can lower token limits after context errors; its overall readiness deadline is checked between individually long requests. That strategy needs explicit semantic constraints and hard deadlines before reuse for billable or mutating routes. The overlapped pipeline exposes detailed stage/count/failure metrics and owns engine/detector cleanup, but queues and retained page state lack aggregate bounds; worker joins and pending waits can be unbounded. Existing output pairs are skipped by presence rather than source/configuration identity. [Client](https://github.com/openbmb/minicpm-ocr/blob/c0881ac7fe9d78623bc222f8ee93e2c722f5413b/sdk/minicpmvocr/backends/client.py), [pipeline](https://github.com/openbmb/minicpm-ocr/blob/c0881ac7fe9d78623bc222f8ee93e2c722f5413b/sdk/minicpmvocr/pipeline/overlapped.py).

Robustness and scheduling fixtures exercise failed-page completion, ordering and bounded configured worker counts; reading these tests does not establish bounded queues, shutdown under every failure or measured throughput. Teamagent should combine candidate-scoring provenance with finite-value validation, explicit unchecked facets, whole-pipeline memory admission and identity-validated output reuse. [Failure fixture](https://github.com/openbmb/minicpm-ocr/blob/c0881ac7fe9d78623bc222f8ee93e2c722f5413b/sdk/tests/test_pipeline_robustness.py), [scheduling fixture](https://github.com/openbmb/minicpm-ocr/blob/c0881ac7fe9d78623bc222f8ee93e2c722f5413b/sdk/tests/test_infer_scheduling.py).
