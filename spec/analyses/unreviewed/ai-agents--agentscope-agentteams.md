## Durable assignments and publication

The manager's taskflow separates prepared and assigned state: it persists the task, publishes its files, sends a Matrix notification using a stable task-derived transaction ID, then records the returned event and republishes metadata. A saved assigned task reuses the recorded notification. Acknowledgement requires a current actor matching the assignee and a room ID. Submission publishes result payloads/deliverables before metadata; a failed sync reports locally persisted state separately from remote publication. These are useful ordering and reconciliation patterns, with actual storage/Matrix guarantees delegated to components outside this review. [Manager taskflow](https://github.com/agentscope-ai/agentteams/blob/ec845f92ed97652272e2d35b2c483e76b6712fd9/manager/src/agentteams_manager/agentteams_manager/tools/taskflow.py#L256-L642).

The TeamHarness submission path compares a result digest against an existing submission and requires its retained submission identity before reuse. Its leader check reports an effective result when task state is submitted and result metadata validates. That is lifecycle/schema validity, not independent acceptance of artifact correctness. Teamagent should keep task ownership, immutable attempt/result identity, publication state and independent verification as separate records. [Result validation](https://github.com/agentscope-ai/agentteams/blob/ec845f92ed97652272e2d35b2c483e76b6712fd9/plugins/teamharness/mcp/lifecycle/taskflow.py#L207-L260), [resubmission](https://github.com/agentscope-ai/agentteams/blob/ec845f92ed97652272e2d35b2c483e76b6712fd9/plugins/teamharness/mcp/lifecycle/taskflow.py#L655-L748), [leader check](https://github.com/agentscope-ai/agentteams/blob/ec845f92ed97652272e2d35b2c483e76b6712fd9/plugins/teamharness/mcp/lifecycle/taskflow.py#L1574-L1591).

## Shared files need versions, not just timestamps

File sync validates relative shared paths, restricts global-shared writes, and bounds the external copy process to 120 seconds. Its single-file push guard compares remote modification time with local mtime using a five-second tolerance. Directory pushes use overwrite mirroring without that per-file guard. More significantly, fixtures explicitly preserve the current limitation: editing an old local copy after another writer's update passes the guard, and an unavailable/unparseable remote-time probe permits copying with a warning. These are observed source/fixture behaviors, not a conflict-safe compare-and-swap protocol. [Implementation](https://github.com/agentscope-ai/agentteams/blob/ec845f92ed97652272e2d35b2c483e76b6712fd9/plugins/teamharness/mcp/artifact/filesync.py#L116-L407), [stale-edit/probe fixtures](https://github.com/agentscope-ai/agentteams/blob/ec845f92ed97652272e2d35b2c483e76b6712fd9/plugins/tests/teamharness/mcp/test_filesync_remote_guard.py#L191-L250).

For Teamagent, record the exact remote version/hash read by an attempt and condition publication on that baseline. Missing version evidence must not silently authorize overwrite. Keep successful local results available while publication is uncertain, and reconcile remote state before reissuing an effect.
