**Static trust-store concern:** [Lookup failure handling](https://github.com/ys-ll/uniterm/blob/871265e77f38343c1f9452b56e22149d5d903b0c/backend/session/hostkey.go#L147-L160) treats a lookup error as first connection, then records and accepts the presented key if the write succeeds. Corrupt/undecodable stored entries therefore need not preserve the previous trust boundary. The [corrupt-store fixture](https://github.com/ys-ll/uniterm/blob/871265e77f38343c1f9452b56e22149d5d903b0c/backend/session/hostkey_test.go#L257-L275) explicitly expects recovery by accepting and recording a key. Teamagent should distinguish truly absent first-use trust from corruption or read failure, requiring deliberate recovery for the latter. This is a source finding, not an executed exploit or a claim that every corrupted file permits connection. Process-local locking and ordinary file replacement also do not establish cross-process atomic trust-store updates.

**Static asynchronous-return concern:** `MCPExec` [defers retirement](https://github.com/ys-ll/uniterm/blob/871265e77f38343c1f9452b56e22149d5d903b0c/backend/session/mcp_exec.go#L146-L188), and `mcpRetireCommand` immediately waits for the command's done channel. Consequently the branch intended to return an ID when the synchronous wait budget ends still runs that blocking defer before returning. The source does not establish the advertised prompt asynchronous handoff for a command still running. Registry expiry also starts at registration, despite a comment describing expiry after completion. These are unexecuted control-flow findings in this module, not a reproduction against a running app.

**Harness consequence:** Keep transport trust, per-command approval and resource ownership separate. A one-use key exception must bind to the exact endpoint/key and remain distinct from permanently changing trust. An async execution response needs cleanup owned by a surviving task or session, with explicit cancellation and completion receipts. Do not infer remote termination from channel closure, or treat a command identifier as sufficient authorization. The inspected Windows-hidden helper queries a file attribute; it offers no evidence about console-window suppression for child processes.
