The complete [approval loader](https://github.com/mvanhorn/agent-tincan/blob/2591cf260438572aed7131c85811fd03c1958d71/internal/policy/approval.go) checks a bounded regular file, restrictive permissions, duplicate keys, unknown fields, nulls and trailing JSON. It reloads on checks and retains the last good gated targets if a later version is invalid. With no usable prior policy, a malformed present file returns an error. **An absent or deleted approval file disables this explicit gate**; separate default holds for particular agent kinds and guest requests still apply. An explicit empty `from` list can override a kind's default. Adoption must preserve this distinction rather than describing all missing configuration as fail-closed. The [approval fixtures](https://github.com/mvanhorn/agent-tincan/blob/2591cf260438572aed7131c85811fd03c1958d71/internal/policy/approval_test.go) cover missing/bad files, duplicate input, same-size/mtime changes and selected urgency behavior.

The inspected [lease fixtures](https://github.com/mvanhorn/agent-tincan/blob/2591cf260438572aed7131c85811fd03c1958d71/internal/relay/leases_test.go#L1-L170) exercise holder conflicts, expiry bounds, quota and administrator distinctions.

**Harness consequence:** Separate authenticated relay identity from action consent, retain host-derived lineage and source taint across handoffs, and repeat admission when the target changes. A coordination lease is useful ownership evidence but does not establish filesystem exclusivity, resource fencing or descendant shutdown. Cross-provider delegation still needs Teamagent's model, account and training-policy checks. Shared note visibility is a separate disclosure decision from a redacted audit record.
