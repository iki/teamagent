## Deterministic authority before model review

The permission path distinguishes allowed, denied and approval-required outcomes, including a `human_only` marker. Self-protection and read-only-mode checks precede later grants. Persistent authority, recognized secret egress, protected files that execute later and unscopable writes have dedicated approval handling. The deliberately dangerous bypass mode clears several of these floors; ordinary bypass, custom grants and auto-review are not equivalent authority settings. This is useful explicit policy structure, not proof that the underlying shell/path/secret classifiers recognize every operation. [Modes and decisions](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/permissions.py#L523-L601), [evaluation ordering](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/permissions.py#L758-L1036).

The engine consults the model reviewer only for eligible approval-required actions, excluding hard denies and human-only asks. It snapshots owner history/context, rechecks reviewer identity and settings epoch after asynchronous review, and rejects changed delegated requests. An exact-action one-use human override is separate from standing grants. Automatic attendance can still use an enabled reviewer; when an unresolved card cannot reach a person, the engine refuses it instead of waiting indefinitely. Thus unattended operation must not be summarized as either universally auto-approved or universally reviewer-free. [Reviewer eligibility and owner input](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/engine.py#L1392-L1491), [snapshot and delegation checks](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/engine.py#L1584-L1731), [authorization](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/engine.py#L1783-L2270).

Inspected approval fixtures reject mismatched grant types, downgrade inappropriate broad grants, preserve valid narrow grants and invalidate a search grant after its provider changes. They are useful acceptance cases; the server-side grant validator itself was not captured. Engine audit emission includes tool arguments and suppresses sink exceptions. Its display-only sidecars and bounded model-facing result call are useful separations, but this boundary alone establishes neither redacted durable audit storage nor fail-closed receipt persistence. [Approval fixtures](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/tests/test_approval_integrity.py), [result/audit boundary](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/engine.py#L2307-L2482).

## Jev decisions and calibration limits

The implemented decision reviewer separates vendor wire formats from deterministic combination logic. The Jev adapter pins `jev-1.13.0`, sends named questions with structured state and parses per-question probabilities; a separate adapter targets a Decisions API. The latter is source evidence of an adapter, not verification of the service's current availability or account access. Missing keys, HTTP errors, timeouts and refusals take an unsure path at the inspected request boundary. An explicitly chosen supported backend without a key does not silently switch reviewers; an unknown stored reviewer name is normalized to the session-model default. [Backend contracts](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/decision_reviewer.py#L864-L1077), [review flow and choice normalization](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/decision_reviewer.py#L1083-L1218).

The combine rules use requested-action, stop and risk thresholds, derive several Jev signals by multiplying component probabilities, and escalate named-target/place mismatches. These products are heuristics unless dependency and calibration assumptions are demonstrated. Upstream comments describe development/sealed evaluations and changes to AgentDojo counts; this review did not inspect the complete benchmark corpus, reproduce those measurements or establish transfer to Teamagent tasks. The character-based state budget is an estimate, not exact tokenizer admission. [Combination rules](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/decision_reviewer.py#L432-L465), [Jev derivation and thresholds](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/decision_reviewer.py#L781-L877).

There is a concrete static validation gap: wire parsing uses `float`, and both combining functions reject values only with `< 0` or `> 1`. A string such as `"NaN"` can therefore become a non-finite value whose risk/stop comparisons are false; an otherwise eligible high-requested action can reach the allow branch. No upstream execution or exploit test was performed. Require finite numeric probabilities, exact question coverage and semantic validation before deriving or combining scores. Also keep model-proposed arguments explicitly untrusted: putting them in a structured evidence object does not establish the module comment's broad claim that the reviewer never sees untrusted content. The engine-generated file-name substring check is a narrow provenance heuristic, not authorization. [Evidence construction](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/decision_reviewer.py#L373-L419), [Jev parser](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/decision_reviewer.py#L993-L1009), [session reviewer boundary](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/reviewer.py#L272-L513).

For Teamagent, admit the decision-model upload itself under account/host/operation/training policy, reserve its resource budget, keep deterministic denials authoritative and version the questions, thresholds, model and evidence. Add non-finite values, missing/duplicate questions, settings changes, timeout and contradictory-signal fixtures before any live ranking or approval use. Neither an API key nor a probability supplies authorization.

## Model routes and truthful readiness

The router lazily caches clients per provider and invalidates them after configuration changes. It strips only recognized provider prefixes; an unrecognized prefix remains part of a native model ID and uses the default provider. This supports IDs containing colons, but Teamagent needs an explicit route manifest to distinguish such IDs from an invalid requested route. The inspected module has no account/training-policy admission. Provider fixtures separately require removed custom routes to fail locally, key changes to rebuild clients and invalid external HTTP endpoints to fail before an HTTP call. Registry/manager enforcement was not itself audited. [Router](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/providers/router.py), [provider fixtures](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/tests/test_provider_router.py#L396-L558).

OpenRouter account sign-in has its own secret profile, PKCE exchange, attempt-bound loopback callback, expiry and authenticated key check before saving. Its passive `connected` status means a stored key exists; it is not a fresh authentication or policy check. Disconnect removes the local profile, not necessarily the remote key. A custom-provider fixture treats a missing model-list endpoint as successful verification with a warning, illustrating why capability discovery, authentication and readiness must remain separate. [Account flow](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/providers/openrouter_auth.py), [verification fixture](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/tests/test_provider_router.py#L495-L558).

The Codex adapter calls an OAuth-backed subscription endpoint, refreshes once after a 401 and translates a 429 to a plan-limit error. It drops output-token, temperature and top-p options from its request. This is not installed-agent discovery, current entitlement verification, a policy exemption or an enforced output-token ceiling. Its client/session header is provider-instance state, not proof of per-task isolation. Provider compatibility comments are upstream observations, not live results from this review. [Subscription adapter](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/providers/codex_provider.py).

## Memory and reusable procedures

The SQLite store uses parameterized queries, a lock, FTS5 triggers/rebuilding and a LIKE fallback that retains the supplied scope predicate. Fallback changes retrieval semantics and ranking: token-prefix/rank search becomes substring/newest ordering. Optional scope is not tenant authorization, and ID-based get/update/delete do not independently enforce an owner. Store-level enumeration/limits are not uniformly bounded. No immutable imported-source versions or audit lineage are established by this store. Inspected fixtures deliberately retain memory already injected into a conversation after deletion and make memory-off stop saving rather than reading. Expose write, retrieval and already-disclosed-context controls separately. [Store](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/memory/sqlite_store.py), [search/fallback fixtures](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/tests/test_memory.py#L729-L843), [deletion/context fixtures](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/tests/test_memory.py#L456-L519), [memory-off fixtures](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/tests/test_memory.py#L563-L600).

Skill selection combines project precedence, personal enablement and session choices, with an off setting overriding selection. Uploads have a staging/confirmation interface, and saving a skill declares approval-requiring metadata. These are useful procedure-lifecycle concepts, but the inspected staging token joins are not validated in this module, ZIP expansion lacks visible entry/expanded-byte quotas and confirmed bytes are not bound to an immutable approved digest. Settings parse failure can become an empty disabled set; writes and multi-file copies do not form an atomic bundle. Caller validation and complete path-race protection were not audited. Use bounded import staging, content hashes, versioned compatibility and explicit promotion grants; installing or suggesting a skill must not enable persistent authority automatically. [Skill store](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/skills/store.py#L258-L620), [skill fixtures](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/tests/test_skills.py).

## Team state, delegation and channel identity

The team store appends an event, folds its projection and advances its head in one SQLite transaction under an in-process lock; projection rebuilding reuses the same reducer. This is a local consistency pattern, not distributed durability. Assignment-derived views and monotonic consumption cursors support separate direct and lead feeds; a delivery page returns its scanned-through sequence even when no visible message results. Advance the consumer cursor only after durable acceptance, and keep delivery distinct from application completion. Workers cannot mark an item done through the inspected status path, and worker transitions require assignment; claims are open by default unless configured lead-only. [Event publication](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/teams/store.py#L193-L288), [feed/cursors](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/teams/store.py#L377-L462), [worker transition and claim rules](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/teams/store.py#L939-L1055).

A separate case journal retains attributed, timestamped payloads, references, entities and taint with a per-case hash chain. Grants include creator, explicit and assignment-specific access; reassignment removes the old assignment grant without deleting unrelated grants. The user role has broad access, so these methods are not independent proof of caller authentication or tenant isolation. The local chain is integrity evidence, not tamper-proof storage; its empty-row verification path does not check the stored head, so complete row erasure is not detected by that method. The query path also fetches rows before applying the returned limit. Retain independently trusted checkpoints, bounded reads and explicit caller authorization before adopting this journal pattern. [Journal and grants](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/teams/journal.py#L105-L353), [chain verification](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/teams/journal.py#L357-L390).

Board creation/assignment and journal grants commit in separate stores, so the individual transaction does not prove atomic cross-store access changes. Journal grants and several attribution fields are outside its hashed fields; the board also supports an explicit space-rekey migration that rewrites its chain. There is no retention/deletion-policy guarantee in these inspected paths. Keep authorization reconciliation, signed/external checkpoints and retention policy distinct from an append-only API shape. [Board/journal sequencing](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/teams/store.py#L567-L625), [assignment sequencing](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/teams/store.py#L973-L1030), [journal hash fields](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/teams/journal.py#L43-L99), [rekey migration](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/teams/store.py#L1370-L1452).

The explorer builds a fresh plan-mode child with selected read/search/Git tools, a default ten-iteration budget and no recursive explorer registration. It returns a final report, with a partial-status warning for an incomplete run. This is bounded delegation intent, not OS confinement or proof that every delegated tool is side-effect-free. Git handoff fixtures distinguish an exact verified commit from a merely successful merge exit, and cover checked-out branches, divergence and dirty-owner preservation. They were read, not run, and establish no signed-publication workflow or live agent correctness. [Explorer](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/coworker/tools/subagent.py#L42-L126), [handoff fixtures](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/tests/test_team_git_handoff.py#L68-L127).

The gateway performs its authorization check before routing messages and buttons, consumes replies that resolve an inbox item before making a new turn, and can park unauthorized input. Origin rendering carries platform/workspace/channel/thread reply arguments, but its pre-approved label is presentation, not a grant or identity proof. The parked store preserves original text and source/thread/workspace context for reviewed redelivery. Fixtures distinguish protected approvals from ordinary questions and reject resolving a Slack-bound approval through Telegram. Preserve the authenticated actor, origin binding, approval identity and eventual delivery receipt independently; the transport authentication implementation was outside scope. ## Speech input

The Rust sidecar performs local dictation with Whisper Base English, averages input channels, resamples to 16 kHz and calls inference with English language and translation disabled. Provisioning downloads a model and verifies expected size/hash after transfer; it is not network-isolated provisioning. The readiness marker compares metadata and its recorded expected hash rather than rehashing weights on every readiness check. Recording accumulation and command waits have no visible duration/size bound in this module; the download has a per-read timeout, not a demonstrated total transfer/byte admission bound. Replacement removes the prior model before rename, so it is not an atomic old-or-new publication guarantee. [Provisioning](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/stt/src/lib.rs#L132-L254), [recording and readiness](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/stt/src/lib.rs#L273-L400), [resampling and inference](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/stt/src/lib.rs#L541-L609).

The inspected GUI fixtures keep Send disabled during recording, insert a transcript as an editable draft, route missing setup to settings and recover from a mocked start failure. They mock Tauri and demonstrate expected UI behavior, not native microphone access, STT accuracy, latency or platform compatibility. This English-only dictation path does not handle the prepared Czech reference, implement Czech-to-English translation, TTS or voice cloning. Preserve explicit language/model selection, approved subtitle wording and the existing media workflow; separate transcript review from authorization to send or execute it. [Voice UI fixtures](https://github.com/andrewyng/openworker/blob/bea25db6f2034ec3093933a267f5933cbea04cd5/surfaces/gui/src/components/Composer.voice.test.tsx).

## Adoption and validation boundary

This is a source-research addition, with no OpenWorker runtime or adapter integrated into Teamagent. Useful candidates are layered action decisions, settings/context invalidation, separate route/readiness states, scoped memory fallback, staged skill publication and editable speech drafts. Deterministic authority, privacy admission, bounded resources, durable receipts and independent artifact verification remain host responsibilities. No comparative benchmark, classifier calibration, retrieval quality, native isolation, provider entitlement or perceptual speech result was measured.
