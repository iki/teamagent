DiskStore saves credential entries to a fresh 0600 temporary file and atomically renames it over the destination; Windows retries only EPERM/EACCES/EBUSY five times with 310 ms total delay, retaining the old value on persistent failure and preserving the original expiry. Fixtures cover concurrent overwrite/read/cleanup, relaxed prior file permissions, retry exhaustion and unrelated errors. Single-use take claims an entry by rename before reading it. This is not complete storage hardening: JSON entries are cast without semantic validation, read errors become null, key sanitization maps distinct punctuation to the same underscore path, existing directory permissions are not tightened, and no fsync/crash-durability guarantee is supplied. Separately updateAuth recomputes currently registered visible tools and replaces handlers when access changes; in-memory fixtures cover revocation, grants, in-place auth mutation and session separation.
