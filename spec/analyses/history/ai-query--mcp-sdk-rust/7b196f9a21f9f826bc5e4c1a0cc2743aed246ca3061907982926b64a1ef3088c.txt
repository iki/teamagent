## Change review - 2026-10-28

**Lifecycle-specific initialization and cancellation-on-drop improve request handling without proving work termination.** Reviewed commit `cd88056ffdc97756fbd98e5a12bbeb41758f0ce8` (commit date `2026-10-26T14:57:21-07:00`). Compared with `8f9a28ecdb5f9237dd7927f915df82cd4d02d09b`; the complete Git comparison contains 55 changed paths.

Client initialization now answers a server ping only while awaiting the initialize response; the discover path deliberately ignores it so a timeout-bounded probe cannot cancel a partially written ping response. New duplex-transport fixtures assert both wire sequences. The server answers bootstrap discovery without committing to a lifecycle, rejects incomplete inline metadata or unsupported versions and keeps waiting, then dispatches the first valid inline request through the service loop so handler notifications can drain. The bootstrap handler receives a disconnected peer.

Convenience client requests now create an abandonment guard after send_request_with_option returns a handle. Dropping the waiting future sends a best-effort cancellation notification; completion disarms it. This does not cover abandonment before a handle is obtained, nor prove the server stopped an operation. The server outbound policy changes from checking association for selected requests to rejecting outbound requests when the recorded peer version is 2026-07-28 or later. Handler dispatch also inserts missing cache hints for that version branch and keeps legacy result shapes/error-code translation separate. These are behaviors of this pinned SDK snapshot; they are not independent confirmation of a published protocol requirement.
