## Change review - 2026-10-28

**Ingestion pins task identity and bounds worker configuration while embedding recovery can alter source coverage.** Reviewed commit `5966db46ab4abc849a2ad668795ee9cb2e5417ef` (commit date `2026-10-27T19:49:36+08:00`). Compared with `2400ca8eb51432b1d304266d0de9ca232d9b53fa`; the complete Git comparison contains 2476 changed paths.

TaskContext captures one unexported task ID for admission, execution and settlement, separates ingestion from memory tasks and passes the relational handle explicitly when loading document/KB/tenant inputs. A missing pipeline version still means latest-at-runtime, so immutable task identity alone is not a reproducible pipeline snapshot. Server wiring validates resolved worker counts/dependencies and starts the ingestor before reporting readiness; its shutdown caller prints completion after Stop without an independently checked result in this module.

Embedding Encode shrinks prefixes only after over-limit errors, then isolates inputs if a whole-batch ladder fails. Transient attempts honor cancellation and share cooldown by model quota identity; waitOutCooldown reads the deadline once, so a later extension by another worker is not rechecked before dispatch. Response cardinality is not checked here: token distribution sizes output from returned vectors, and the isolated path indexes result zero directly. Usage totals are apportioned from locally counted sent prefixes, not per-input provider measurements; truncated source coverage is not represented in the returned Vector/TokenCount pair.
