**Database targeting and export-key semantics prevent cross-database setup and duplicate semantic keys.** Reviewed commit `0b9e2484b530e1e5352c399b46a4a59c39f7a68f` (commit date `2026-10-27T17:12:06+01:00`). Compared with `690a0e83654dd08e7613127fc0778786c0228a5e`; the complete Git comparison contains 45 changed paths.

Neo4jWriter now passes its configured database to both temporary-index setup and cleanup sessions instead of relying on the driver's default database. VectorCypherRetriever consistently uses the embedding-property attribute populated by index metadata on normal and fallback query construction. Parquet export preserves an existing semantic KEY, including composite keys, and adds uniqueness for synthetic __id__ relationship joins when necessary instead of introducing a second KEY. Mixed list element types are now detected across rows and stringified when they cannot share numeric/list representation; this avoids Arrow type errors but changes value types and emits only a warning. Numeric int/float mixes remain on the numeric path, so lossless preservation must be checked against concrete Arrow width/precision rather than inferred from a comment.
