**Enterprise identity exchange and machine credentials remain distinct negotiated authorization profiles.** Reviewed commit `15ca394e00a66434520b9ade26294999295a43ae` (commit date `2026-10-23T17:24:05+01:00`). Compared with `fb374c7db2b34f18ca9183882e0beecdf661892b`; the complete Git comparison contains 6 changed paths.

The six-path comparison adds versioned and draft Client Credentials and Enterprise-Managed Authorization specifications plus repository metadata. The versioned client-credentials document describes pre-registered machine identities and excludes dynamic registration, but contains an interoperability inconsistency: prose/example put client_secret in the request body while metadata names client_secret_basic. That discrepancy needs resolution against the actual negotiated implementation before transmitting credentials. Enterprise authorization separates the IdP, resource authorization server and MCP resource server. Token exchange audience is the resource authorization-server issuer; optional resource identifies the MCP server, and the issued access token must be restricted to that resource. The IdP evaluates administrator policy during issuance, but the document explicitly says it cannot observe subsequent MCP traffic. These are specifications, not evidence that an SDK, provider or Teamagent implements the profiles.
