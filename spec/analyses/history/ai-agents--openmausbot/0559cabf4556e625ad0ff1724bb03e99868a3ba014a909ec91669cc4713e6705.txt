## 2026-10-28 scoped update review

Reviewed commit `1908b929057150ff621262bb13a2183787f6c66f` (commit date `2026-10-27T21:36:33+05:30`). The original snapshot above remains historical evidence.

**Scope:** Complete browser session/profile helpers, their mocked fixtures and shared tool-name aggregation helper; server session/authentication, pairing redemption, MCP OAuth and backend grants were not audited.

The [browser session reader](https://github.com/milind-soni/OpenMausBot/blob/1908b929057150ff621262bb13a2183787f6c66f/src/lib/session.ts#L31-L77) distinguishes unreachable and unauthenticated responses, but any successful body not matching its session shape falls back to loopback. Unless that body explicitly declares service trust, the UI treats it as connected and owner/admin; even a successful malformed JSON response becomes an empty body then owner UI state. This is a concrete frontend trust-state problem, not evidence of a server authorization bypass. Teamagent should reject unknown successful response shapes and require an explicit validated local-owner variant.

[Profile selection](https://github.com/milind-soni/OpenMausBot/blob/1908b929057150ff621262bb13a2183787f6c66f/src/lib/session.ts#L18-L29) avoids displaying the configured owner's identity to ordinary sessions with a different or missing email. Pairing/sign-in helpers remove sensitive fragment values from the current address/history before redemption, and browser grants carry a stable attempt ID for retries. The fallback attempt-ID generator uses Math.random when randomUUID is unavailable, so it is not an adequate basis for the comment's unpredictability claim. Server-side one-time use, retry binding and credential storage were not inspected; the fixtures mock those responses rather than proving redemption behavior.

The [tool-name helper](https://github.com/milind-soni/OpenMausBot/blob/1908b929057150ff621262bb13a2183787f6c66f/shared/tool-name.ts) separates command-looking display titles from aggregate tool buckets to avoid grouping by raw commands. Its whitespace/slash heuristic can still miss a single-word command or misclassify a namespaced tool. Teamagent should receive canonical tool identity separately from a bounded redacted display label, never infer authority or audit identity from presentation text. No frontend fixtures, browser flows or server/provider calls were executed.

**Verification limit:** source inspection only; no upstream tests or provider calls were executed. This scoped review does not certify every file in the repository.

## 2026-11-01 scoped source review

Reviewed frozen commit `9230dc9b71a22375a9d3b296172b5664c2ae3201` against prior analyzed commit `ae1aada6b67b68d03921f910f4b4b97a66cea1a7`. Historical reviews above remain separate evidence.

The [permission proxy](https://github.com/milind-soni/OpenMausBot/blob/9230dc9b71a22375a9d3b296172b5664c2ae3201/server/permission-proxy.ts) binds each pending answer to its originating socket. A dropped connection settles only that socket's requests as unavailable; later requests can reconnect with short connection retries. Permission unavailability returns deny, while a question returns an MCP error and directs the assistant to ask visibly rather than manufacturing a user answer. The [socket fixtures](https://github.com/milind-soni/OpenMausBot/blob/9230dc9b71a22375a9d3b296172b5664c2ae3201/server/permission-proxy.test.ts) cover broker disappearance, pending questions, no approval during outage and successful later reconnection.

The visible receiver still buffers without a line/byte cap and parses broker JSON through dynamic values. Reconnection alone also does not prove the new broker belongs to the same session, despite a startup comment implying it: Teamagent needs an authenticated session epoch, schema/size limits and explicit connect/answer deadlines. The [Claude recovery delta](https://github.com/milind-soni/OpenMausBot/blob/9230dc9b71a22375a9d3b296172b5664c2ae3201/server/drivers/claude-auth-recovery.ts) and [fixture](https://github.com/milind-soni/OpenMausBot/blob/9230dc9b71a22375a9d3b296172b5664c2ae3201/server/drivers/claude-auth-recovery.test.ts) carry engine/model/credits scope with quota refusal after process stop, avoiding a model-specific limit being treated as a provider-wide outage. Neither connection recovery nor quota classification authorizes replay of an ambiguous action.

**Coverage:** Read the complete four-file targeted permission-proxy and refusal-recovery delta. Broker authentication and full driver retry policy remain outside scope. Source inspection only; no upstream tests, source programs or live providers were executed. This is a scoped architecture review, not a whole-repository correctness or security certification.

## External-update review - 2026-11-01

Reviewed `6e32504b9d08674834bef034d76787751f39d9a3` against `9230dc9b71a22375a9d3b296172b5664c2ae3201`.

The 47-path update extends the [Electron permission policy](https://github.com/milind-soni/OpenMausBot/blob/6e32504b9d08674834bef034d76787751f39d9a3/electron/app-permissions.mjs) so notifications can be requested by the currently active remote server as well as the home origin. Admission requires the main window's web-contents identity, an explicitly true main-frame flag, and a matching parsed web origin. The active origin is obtained at the decision boundary, so removing it also removes that eligibility instead of leaving a stale allowlist entry.

The complete inspected [permission fixtures](https://github.com/milind-soni/OpenMausBot/blob/6e32504b9d08674834bef034d76787751f39d9a3/electron/app-permissions.node-test.mjs) deny other windows, subframes, other origins, unknown frame state and opaque URLs. They keep geolocation, camera, clipboard and fullscreen denied in this policy rather than generalizing a notification exception to every capability.

**Harness consequence:** Bind desktop capability grants to the current connection, exact origin, owning window and frame, and revoke eligibility when the connection changes. This is application-level eligibility, distinct from browser/OS permission and user consent. The review covers both complete deltas; actual Electron permission events, native notifications, packaged applications and the other changed files were not executed or audited.
