**Partial-answer handling and explicit provider routes improve client semantics, while cloud schema operations remain delegated.** Reviewed commit `b81465d9ad3d80ee1df344508a85d1f2cdfb8a26` (commit date `2026-10-27T22:07:20+08:00`). The answer-lane client now reads the first completion choice and checks its finish reason against the imported cut-short set. On a match it raises an error carrying partial_answer, and attaches usage for own-model chat, instead of returning an apparently complete string. Missing response shape still includes up to 200 characters of the raw envelope in its diagnostic. Native Responses/Messages paths explicitly refuse claude-code/ routes; the Anthropic runner likewise rejects a Claude Code route and requires a selected model. These dispatch guards do not verify the uninspected subprocess/provider implementation or the full set of cut-short reasons.

Cloud metadata-schema methods are thin cloud-mode-gated delegations; local mode has no equivalent. The docstrings describe declaration as removing incompatible existing metadata and describe account/folder inheritance, but the server behavior is not implemented in this client file. Mock HTTP fixtures cover encoded folder IDs, PUT/GET/DELETE methods and a 30-second request timeout, not remote validation or migration durability.

PDF extraction adds per-character-code advance widths for simple fonts and Identity-H composites and shares the computed pen end across decomposed characters from one code. Type 3 and unsupported mappings deliberately retain the prior geometry fallback. Numeric parsing accepts float values without a finite-value check; range-form widths cap the code range, while explicit width arrays are fully materialized. Heading reconciliation accepts an exact normalized title on the page following a bookmark; fuzzy/suffix matching remains limited to same-page headings.
