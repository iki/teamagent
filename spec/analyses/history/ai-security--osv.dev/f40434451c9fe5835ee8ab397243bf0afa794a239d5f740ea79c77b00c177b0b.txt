## Source update reviewed 2026-10-28

Reviewed commit: [`083210c7e7923eccd17278305cbe1fef27309c00`](https://github.com/google/osv.dev/commit/083210c7e7923eccd17278305cbe1fef27309c00). Scope: Full source-repository sync script and CloudStorage interface/GCS implementation read. Feed generation, allowlist sync and live cloud behavior were not audited.

The [source sync script](https://github.com/google/osv.dev/blob/083210c7e7923eccd17278305cbe1fef27309c00/tools/sourcerepo-sync/source_sync.py) defaults to dry-run/test resources, rejects duplicate source names and local copies of dynamic sync fields, and has validation-only mode before cloud access. Actual synchronization can delete absent sources, is not transactional and skips new attributes absent from an existing datastore record. Adapt explicit desired-versus-runtime fields and a reviewable plan, with stronger schema validation, deletion authorization and optimistic concurrency.

The [storage contract](https://github.com/google/osv.dev/blob/083210c7e7923eccd17278305cbe1fef27309c00/go/osv/clients/cloudstorage.go) exposes generation preconditions, object metadata and streamed writes. The [GCS adapter](https://github.com/google/osv.dev/blob/083210c7e7923eccd17278305cbe1fef27309c00/go/osv/clients/gcs_client.go) translates generation zero into create-only semantics and bounds retries to three attempts. Its streamed retry only rewinds io.Seeker values: a transient failure can otherwise retry from a partially consumed non-seekable reader. Backoff sleeps are not context-selectable, reads use unbounded ReadAll, and bucket wrappers close a shared client. Teamagent should require replayable input or a fresh-reader factory, bounded reads, cancellable waits and explicit client ownership. No cloud access, synchronization or tests were executed.

Citations below identify current lines visible in the captured committed diff; this is a scoped assessment, not a whole-repository audit.

Shadow comparisons use non-blocking semaphore admission: a full pool drops a shadow with a warning instead of queueing it. Admitted work detaches from caller cancellation and receives a separate timeout; deferred cleanup releases capacity and accounts for completion. This protects foreground latency but means a shadow sample can be missing, and the timeout still depends on the worker honoring its context. Comparison coverage and dropped samples must accompany any agreement metric. Panic logs include a stack and value, so diagnostic confidentiality needs a separate policy. [go/internal/database/dualread/vulnerability.go](https://github.com/google/osv.dev/blob/2550f6d61565de3a813e19f64a24b04b8af0ce39/go/internal/database/dualread/vulnerability.go#L121-L145).

The Git synchronization branch now fetches/prunes/forces tags explicitly. Mutable tag names therefore cannot serve as durable evidence identities. Teamagent retains immutable reviewed commit/object evidence independently and does not transplant these force-update semantics into a user's dirty checkout. No fetch or shadow workload was run here. [go/cmd/gitter/git.go](https://github.com/google/osv.dev/blob/2550f6d61565de3a813e19f64a24b04b8af0ce39/go/cmd/gitter/git.go#L117-L125).

[PostgreSQL lookup validation](https://github.com/google/osv.dev/blob/c4dbe744f53244c634bceba56435a77f5c5d8a60/go/internal/database/postgres/vulnerability.go) rejects invalid UTF-8 and NUL-containing text before batching. [Package/cursor matching](https://github.com/google/osv.dev/blob/c4dbe744f53244c634bceba56435a77f5c5d8a60/go/internal/database/postgres/vulnerability_matching.go) repeats the text check after URL normalization; encoded invalid bytes therefore cannot bypass the original check. Invalid IDs become not-found, malformed package names yield no matches, and invalid cursors remain errors. Those result semantics must remain visible to a security consumer: an invalid query is not evidence that a valid package has no vulnerabilities.

The [matching fixtures](https://github.com/google/osv.dev/blob/c4dbe744f53244c634bceba56435a77f5c5d8a60/go/internal/database/postgres/vulnerability_matching_test.go) teach the fake database to reject invalid text, cover a valid sibling beside an invalid batch query and retain binary commit bytes as valid `BYTEA`. This is more representative than unrestricted string equality, although the fake shares the production predicate and no real PostgreSQL behavior was executed here.

The [importer](https://github.com/google/osv.dev/blob/c4dbe744f53244c634bceba56435a77f5c5d8a60/go/internal/importer/importer.go#L615-L657) hashes source data before normalization. The [new JSON escape transformer and tests](https://github.com/google/osv.dev/blob/c4dbe744f53244c634bceba56435a77f5c5d8a60/go/internal/osvutil/schema/schema.go#L75-L114) distinguish a NUL escape from an escaped literal backslash, clone only when rewriting and preserve the caller's slice.
