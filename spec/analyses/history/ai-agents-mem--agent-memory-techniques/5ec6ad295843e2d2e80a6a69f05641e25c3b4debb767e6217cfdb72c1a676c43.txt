## Change review - 2026-10-28

**Four memory notebooks illustrate persistence, sharing and evaluation while retaining demo-only authority and budget gaps.** Reviewed commit `6e8fb023235e3f3ecd2d2d122b94fa86a4bf9118` (commit date `2026-10-27T16:12:51+02:00`). Compared with `4767c0341ccd8b714147334c5f17c26ff99d8e41`; the complete Git comparison contains 33 changed paths.

The cross-session example uses parameterized SQLite persistence but defaults to an in-memory database and INSERT OR REPLACE with no revision predicate. Loading strategies mutate the loaded state; last_n/summary can therefore discard message history when that state is saved. Model-extracted facts replace prior facts and are inserted into a system prompt as known user facts without source provenance or confidence validation.

The shared-memory example checks an in-process ACL and locks writes, but version_check only rejects a stale version when the caller supplies expected_version; the agent's write wrapper omits it. Reads return mutable entry objects rather than immutable copies, and summary/history methods do not take an agent identity. Namespace/key concatenation and caller-supplied identities are illustrative storage choices, not an authenticated cross-agent boundary.

The evaluation notebook parses judge JSON without semantic score validation, substitutes 0.5 on parse failure and silently drops malformed contradiction responses. Contradictions are searched only within batches yet divided by all possible global pairs, so the reported rate understates unexamined cross-batch pairs; zero temporal cases return score 1.0 with n_cases zero. These are unsuitable as acceptance metrics without explicit missing/error/coverage states.

The production-pattern notebook simulates stores and embeddings. Its graph queries key only by entity/relation despite edges carrying user_id. Cost limits report a boolean but the inspected ingestion/extraction paths do not enforce it before work, and the monthly comparison uses total ledger spend rather than a calendar window. Extraction sends raw text before later fact redaction, accepts unvalidated parsed structures and treats malformed JSON as an empty successful extraction.
