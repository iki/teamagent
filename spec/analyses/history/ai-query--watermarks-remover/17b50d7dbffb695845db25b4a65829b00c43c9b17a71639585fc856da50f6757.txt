## Change review - 2026-10-28

**Office add-in inspection gains bounded XML parsing, while cleanup remains destructive to provenance and add-in state.** Reviewed commit `5c180932a00c793261177f79aee21db8929f3fe2` (commit date `2026-10-21T16:02:50-06:00`). Compared with `1181fd4e8cc581931a5ee672697a646721e92c78`; the complete Git comparison contains 23 changed paths.

OOXML inspection now recognizes Word/Excel/PowerPoint webextensions parts and reports parsed property/reference names without scanning visible body text as vendor evidence. A streaming XML target rejects DOCTYPE, stops after 30 findings and avoids building a tree. The collector suppresses those stops and malformed-XML errors and returns the findings accumulated so far without a distinct truncation/error field. Known vendor prefixes produce a confirmed classification, but a property name is evidence of that metadata field, not proof that document content was generated by the vendor.

Cleanup drops every webextensions part, associated content-type overrides and dangling relationships, including non-AI add-in state. It also continues dropping custom XML and provenance fields. New Office owner-file checks occur before CLI backup and before library destination creation, with fixtures asserting original bytes/no backup/no destination on refusal. Those sibling-file heuristics are useful warnings, not a held file lock or protection against a document opening afterward. ISO-BMFF detection now requires at least eight unparsed trailing bytes before raw-marker recovery, avoiding false manifest findings from one-to-seven-byte padding; a raw recovery match still is not cryptographic provenance verification.
