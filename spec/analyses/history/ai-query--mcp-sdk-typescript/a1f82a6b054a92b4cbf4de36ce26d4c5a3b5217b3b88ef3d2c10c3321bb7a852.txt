## Change review - 2026-10-28

**OAuth compatibility hooks expose provider policy and audience validation stays opt-in.** Reviewed commit `b415e60bdf0e8dd5d6cbe7e6353abfb982b06dd2` (commit date `2026-10-26T14:29:44Z`). Compared with `8aabbdcef6e016978a3132045281dfbd51c69792`; the complete Git comparison contains 184 changed paths.

The client adds a default-false option suppressing its added offline_access consent prompt and a scopeForRefresh callback. Refresh scope is omitted by default even when stored tokens contain one; a nonempty supplied scope is sent and becomes the returned scope when the server omits it or sends an empty string. The callback's documented restriction to originally granted scopes is not checked in these call sites. A callback exception propagates before starting a refresh or a new authorization, as the added mocked fixtures assert. Response scope still wins when nonempty, and refresh-token rotation preserves a returned replacement.

Legacy bearer middleware gains expectedResource: when configured, it rejects missing/mismatched verifier-reported audiences before checking scopes. Comparison ignores URL fragments and one trailing slash; it is not default-on and depends on the verifier's evidence. Fixtures cover other origins, schemes, ports, paths and query tenants. Server change events now forward notification params, overriding forwarded resource URI with the event URI; subscription-ID stamping remains the listen router's responsibility. The POST handler now returns Allow: POST on its 405 responses and checks header declarations even for the relevant partially invalid schema case.
