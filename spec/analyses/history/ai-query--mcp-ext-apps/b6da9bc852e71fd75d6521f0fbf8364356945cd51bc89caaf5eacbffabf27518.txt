## Change review - 2026-10-28

**Default-on WebMCP bridging expands the tool surface and requires the same host authorization and bounded validation.** Reviewed commit `07cda2513b0b691ac261ac69c856062c9afb2824` (commit date `2026-10-27T09:03:11Z`). Compared with `82221c0c8ce7661efa6771c9d461511b1650495f`; the complete Git comparison contains 48 changed paths.

The App now bridges registered tools into document.modelContext and page tools back into Apps tools/list and tools/call by default, with an explicit false option. App registrations take name precedence and mirrors are not echoed. Page tools are restricted to the current frame when a window is supplied, while descriptors with no window are accepted. Descriptors are read once and copied to plain JSON; malformed names/descriptors are dropped, object schemas are coerced to MCP's object shape, and an implementation compatibility heuristic serializes every call's input when any frame tool reports its schema as a string.

Page calls forward the request AbortSignal, wrap non-object results and translate errors into isError. Mirror controllers are aborted and change listeners removed on close, then mirrors re-established on reconnect. Registration failures only warn; a broken model context becomes an empty list or not-found response. Neither bridge path shown adds its own input-schema enforcement, result byte limits, tool-count limits or authorization check. The internal test polyfill ignores cross-frame exposedTo, performs JSON copying and explicitly leaves an executing tool running when it is unregistered. It is a realm-local fixture, not native browser security evidence.
