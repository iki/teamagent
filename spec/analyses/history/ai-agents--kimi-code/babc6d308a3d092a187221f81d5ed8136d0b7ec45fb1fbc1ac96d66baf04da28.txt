## 2026-10-28 scoped update review

Reviewed commit `68a283894163204e93b072cef20db164015a5cad` (commit date `2026-10-27T18:59:19+08:00`). The original snapshot above remains historical evidence.

**Scope:** Complete OAuth region profile/resolution module, region cache, public export facade and region fixture. New stateful resolver, local-signal inference, token storage/refresh and node/ACP sessions were not audited.

The [region resolver](https://github.com/MoonshotAI/kimi-code/blob/68a283894163204e93b072cef20db164015a5cad/packages/oauth/src/region.ts#L209-L242) preserves the selection source and explicitly orders environment, recognized login, default credential slot, install marker and default. The [login-host helper](https://github.com/MoonshotAI/kimi-code/blob/68a283894163204e93b072cef20db164015a5cad/packages/oauth/src/region.ts#L94-L114) yields to environment overrides rather than silently replacing them after a UI region choice. This is useful configuration provenance, but host recognition is string comparison after trimming/trailing-slash removal, not URL canonicalization, endpoint authorization or token-audience validation. An unknown environment host receives the mainland-cn regional label, while an unknown persisted host falls through to marker/default; preserve the effective custom endpoint separately from that coarse label.

The [Remote Control selection](https://github.com/MoonshotAI/kimi-code/blob/68a283894163204e93b072cef20db164015a5cad/packages/oauth/src/region.ts#L249-L296) selects credential slot and relay together and prevents an install marker from moving an unrecognized custom login to the global relay. It can deliberately return a global region alongside a custom credential key and mainland relay, as the [fixture](https://github.com/MoonshotAI/kimi-code/blob/68a283894163204e93b072cef20db164015a5cad/packages/oauth/test/region.test.ts#L350-L381) records. The profile omits global telemetry with instructions to skip it, but senders were not reviewed; the content CDN helper explicitly uses the mainland host for both regions. Thus neither region selection nor a missing telemetry endpoint proves comprehensive regional isolation or that all clients obey the profile.

The [cache](https://github.com/MoonshotAI/kimi-code/blob/68a283894163204e93b072cef20db164015a5cad/packages/oauth/src/region-cache.ts#L19-L71) validates fixed version/auth-state/region/source fields and attempts to delete malformed entries, while reads, writes and deletion swallow I/O failures. Writes are direct rather than atomic and have no record age or local file-size bound. The [stateful resolver fixture](https://github.com/MoonshotAI/kimi-code/blob/68a283894163204e93b072cef20db164015a5cad/packages/oauth/test/region.test.ts#L138-L308) distinguishes unreadable auth from logged-out inference, checks cache clearing on login and disables inference for explicit overrides. That implementation was outside this scope, and no fixture ran. Adapt explicit selection provenance and unavailable-state handling, with immutable profiles, bounded atomic cache persistence and separately verified credential/transport binding.

**Verification limit:** source inspection only; no upstream tests or provider calls were executed. This scoped review does not certify every file in the repository.
