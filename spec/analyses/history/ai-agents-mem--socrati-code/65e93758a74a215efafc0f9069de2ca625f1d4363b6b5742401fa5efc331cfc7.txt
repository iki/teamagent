## Change review - 2026-10-28

**Ambiguity limits stop definition resolution and report totals, while Qdrant retry is narrowly targeted.** Reviewed commit `dae6d3a073f9b2df08b52921b08640ceb4e1330a` (commit date `2026-10-24T00:34:57+01:00`). Compared with `1e829bf7ddf1e34c4cc6713227f00422cee791cc`; the complete Git comparison contains 37 changed paths.

The impact, flow and symbol tools accept an optional positive integer limit and display shown-versus-total counts with file-narrowing advice. getSymbolContextResult stops after that many successfully resolved definitions, reports the filtered name-index total/file count and releases its reader token in finally; a stale entry does not consume the result allowance. New mock fixtures check that a limit of one reads one valid definition payload and can advance past a stale one. The limit is neither a mandatory default nor a hard service maximum, and each selected definition can still expand all callers/callees. Totals describe index matches, including unresolved entries, rather than a verified complete result set.

The symbol store wraps its Qdrant operations with one retry only when an UND_ERR_SOCKET code appears within five cause-chain entries. A second failure or other error propagates. This recognizes that a server may have applied the first request; deterministic IDs and replay-safe operations matter. Collection creation already accepts an already-exists response. The wrapper itself provides no backoff, deadline or cancellation, and replaying a destructive collection operation is not a concurrency-safe transaction when another actor can recreate or modify the collection between attempts.
