## Operations and ownership

Keep inspection/conversion, speech-to-text (STT), text-to-speech (TTS), voice enrollment, reference-conditioned synthesis and voice conversion distinct. Enrollment creates or registers a reusable voice resource; it does not necessarily train a model. TTS turns text into speech. Voice conversion transforms an existing performance. Avatar animation is a video operation and needs independent lip-sync, identity and GPU-resource decisions.

Portable domain code owns requests, capability constraints, deterministic selection, result schemas and state transitions. Host adapters own subprocesses, HTTP, devices, codecs, credential lookup and temporary artifacts. Each adapter returns typed failures for unavailable, unsupported, unauthorized, invalid input, timeout, cancellation, rate limit and partial output. It must not convert an unsupported feature into a successful empty result.

A media result includes artifact identity/hash, detected format, sample rate, channels, duration, engine/provider and model revision, effective device, processing parameters, timing, warnings and original-source linkage. Transcripts additionally contain language evidence, segments, optional word timing and optional speaker labels with their method. Absent timing or diarization is absent capability, not fabricated zeros or a default speaker. Provider confidence and model scores are not interchangeable probabilities.

## Comparative voice evaluation

A meaningful comparison separates naturalness, reference-speaker fidelity, intelligibility, pronunciation, expression control, cross-language identity, long-form consistency and editability. A system can improve one and regress another. Use blind paired listening with identical permitted samples and held-out text, native-language raters, randomized order and confidence intervals. Include Czech when relevant, code identifiers, numbers, emotion tags, whispers, long passages and noisy reference recordings. Do not generalize an English controlled-voice leaderboard to every speaker or language, and do not reproduce Astra's unverified Elo values as this harness's results.

Measure end-to-end first audible sample, p50/p95 latency, sustained throughput, cancellation-to-silence, failed/partial generations and total cost per accepted output. Distinguish warm models, cold startup, queueing, network time and local codec conversion. Price tags in bytes, characters, credits, audio seconds and monthly capacity need separate estimators; mixed-language UTF-8 text makes a universal characters-to-bytes multiplier invalid. Keep enrollment, storage and repeated failed attempts in the cost record.

Use a constrained Pareto set of measured quality, latency, cost and reliability after privacy, license, language and voice compatibility filters. A weighted/JEV-style decision can rank feasible candidates only with explicit weights, dated evidence and uncertainty. Retain a deterministic configured order when measurements are missing. Promotions should require a held-out improvement and negative tests for unready voices, wrong language, revoked references, unsupported formats and explicit override failure. Free capacity can be an optional experiment tier; it must never silently turn into a paid fallback.

## Selection without hidden fallback

First filter by operation, privacy/egress permission, required language, voice compatibility, timing/diarization needs, supported format, readiness, resource budget and deprecation policy. A configured executable is not a loaded model; a key is not an entitlement; a visible GPU is not a supported inference runtime. Return the reasons each candidate was rejected.

Then apply a documented stable preference order, optionally using measured profiles for the actual device/model pair. Start with local-ready candidates when local processing is requested; cloud candidates require permission to transmit the content. Support explicit backend/model/voice/device overrides. If an override cannot satisfy the request, fail with its reason rather than quietly choosing a different backend, language, voice or billable service. Any opt-in fallback needs its own recorded transition and must preserve hard constraints.

Later, measured profiles can estimate expected task value: recognition accuracy or listener preference minus latency, financial cost, privacy exposure and failure risk. These are calibrated decision inputs, not values an LLM can invent. Bound exploration to permitted candidates and non-sensitive evaluation samples; do not explore a new cloud provider on private production audio. Store profile age and uncertainty. A deterministic baseline remains necessary when measurements are missing.

## Codec and artifact pipeline

Inspect bytes/container streams before choosing an operation. Record the original hash and stream metadata, then decode only the selected track. Bound compressed bytes, decoded samples, channel count, duration, subprocess time and output size. Do not accept a file extension or HTTP Content-Type as sufficient validation. For media containers, explicitly distinguish no-audio-track, unsupported codec and decode failure.

Convert through an explicit trusted executable with an argument array and a contained temporary/output path. Preserve the original; derived PCM, transcript and final audio each get hashes and transform provenance. For a conservative local STT path, produce mono PCM16 WAV at 16 kHz. This is an adapter choice, not a universal format: OpenAI live transcription documents 24 kHz PCM, while output speech rates depend on engine/voice. Avoid repeated lossy re-encoding. Preserve separate channels when the requested speaker method relies on channel separation, and record any downmix that removes that information.

Raw PCM has no container header. Its endian, sample representation, rate and channel count must travel with the bytes. JSON containing an audio artifact reference is not audio. Validate bounded response bodies before publication, and verify the produced container rather than assigning a MIME type from the requested extension. Streaming network bytes may still contain a complete sentence rendered in advance; measure first-audio delay separately from sustained synthesis rate.

## Current hosted API contracts

All facts in this section were checked against primary documentation on 2026-10-25; they are not guarantees about an account's entitlement. Keep model IDs configurable and version capabilities. Provider limits are ceilings; the harness may impose smaller explicit limits.

**OpenAI file STT.** Send multipart `file` and `model=gpt-transcribe` to `https://api.openai.com/v1/audio/transcriptions` with server-held Bearer authorization. The guide lists a 25 MB upload limit and common audio/video containers. Parse the documented response for the selected model; do not assume legacy verbose JSON, word timestamps or speaker labels are available for every model. Earlier Whisper/GPT-4o transcription models and the translation endpoint are documented as deprecated with shutdown on 2027-02-26. [Official guide](https://developers.openai.com/api/docs/guides/speech-to-text).

**OpenAI TTS compatibility.** The existing `POST https://api.openai.com/v1/audio/speech` accepts JSON `model`, `input`, `voice`, optional `instructions` and `response_format`, and returns audio. Input is limited to 4,096 characters; formats include MP3, Opus, AAC, FLAC, WAV and PCM. The current reference lists the legacy models. [Speech endpoint reference](https://developers.openai.com/api/reference/resources/audio/subresources/speech/methods/create). The guide now retires `tts-1`, `tts-1-hd` and `gpt-4o-mini-tts` on 2027-01-06 and directs migration to Realtime `gpt-realtime-2.1-mini`, which is not accepted by this endpoint. Treat the legacy adapter as explicit compatibility mode; a new model ID alone is not a migration. AI speech disclosure is also a provider requirement. [Official TTS guide](https://developers.openai.com/api/docs/guides/text-to-speech).

**ElevenLabs file STT.** Send multipart `file`, `model_id=scribe_v2` to `https://api.elevenlabs.io/v1/speech-to-text`, using `xi-api-key`. The documented result has text/language and timed `words` entries; request diarization explicitly when needed. The API permits files from 100 ms to below 5 GB, but the harness should use smaller bounded uploads. Raw `pcm_s16le_16` means 16 kHz, 16-bit mono little-endian audio. Do not silently substitute a provider-fetched URL for an uploaded file. Disabling logging requires the documented enterprise capability. [STT reference](https://elevenlabs.io/docs/api-reference/speech-to-text/convert).

**ElevenLabs TTS.** Send JSON `text`, explicit `model_id` and supported voice settings to `https://api.elevenlabs.io/v1/text-to-speech/{voice_id}/stream`, with `output_format` in the query and `xi-api-key` authentication. The response is audio bytes. Format availability can depend on subscription; validate the chosen codec/rate and preserve the actual response type. The documented default model is `eleven_multilingual_v2`; use configured capabilities instead of assuming it is the latest or best model. [TTS streaming reference](https://elevenlabs.io/docs/api-reference/text-to-speech/stream).

Keep origins fixed for built-in providers and reject credential-bearing redirects. A custom endpoint is a separate trusted configuration, not an arbitrary URL supplied by the model. Map structured error codes without logging provider bodies that may contain input. ElevenLabs distinguishes temporary request/concurrency limits from authentication, permissions and payment errors. [Error reference](https://elevenlabs.io/docs/eleven-api/resources/errors). OpenAI likewise distinguishes temporary rate limiting from credit/spend/quota failures; retry only the former, honoring `Retry-After` within a bounded deadline. If the required delay exceeds the budget, defer instead of retrying earlier. [OpenAI errors](https://developers.openai.com/api/docs/guides/error-codes).

## Voice resources and supported cloning

Support authorized voice cloning as an explicit operation with provenance. A voice resource records owner/workspace, provider or local backend, resource ID, reference artifact hashes, consent/rights evidence reference, allowed uses, access scope, model compatibility, creation time, verification status, expiration/revocation and deletion state. Consent evidence is separate from a recording merely being accessible. Do not infer a real identity from speaker embeddings or from a successful clone request.

ElevenLabs IVC uses multipart `name` and repeated `files` at `POST /v1/voices/add`, with optional description and processing options. The result includes `voice_id` and `requires_verification`; preserve that state rather than reporting an immediately usable voice. The API schema does not provide a universal consent-document field. [IVC reference](https://elevenlabs.io/docs/api-reference/voices/ivc/create). Its user workflow explicitly requires confirmation of rights and consent; retain corresponding harness evidence and expose provider verification steps. [Cloning guide](https://elevenlabs.io/docs/eleven-creative/voices/voice-cloning/instant-voice-cloning).

OpenAI recording-based custom voices require eligible account access, a separate consent recording and a matching reference sample. Create consent via multipart `name`, `language`, `recording` at `/v1/audio/voice_consents`, then create a voice using `name`, `audio_sample`, `consent` at `/v1/audio/voices`. Samples are limited to 60 seconds; use the current provider consent phrase and applicable upload requirements. Prompt-created voices have a different compatibility contract and are not recording-based clones. [Custom voices guide](https://developers.openai.com/api/docs/guides/custom-voices).

For local [Chatterbox](https://github.com/resemble-ai/chatterbox) ([review](projects/external--chatterbox.md)), enrollment may register a reference plus metadata, while synthesis computes conditioning later. Protect embeddings, checkpoints and reference audio with the same access/retention scope. Preserve synthetic provenance and model watermarking; do not describe watermark presence as guaranteed detection after every edit/transcode. Revocation prevents future synthesis and removes retained reference/derived resources according to policy; it cannot retract already delivered audio. Deleting a local record and deleting a provider voice are distinct confirmed operations.

An enrollment request is resource creation. After a timeout with unknown upstream outcome, do not blindly replay it and create duplicates. Keep a pending receipt and reconcile provider state or require an explicit retry. Never treat a verification-required or revoked voice as ready merely because a string ID was returned.

## Quality, latency, cost and acceptance

Build held-out speech sets spanning target languages, accents, device noise, quiet speech, names, numbers, code identifiers, overlap and silence. Measure WER/CER plus task-specific entity/command error, timestamp drift and diarization error with stated overlap/collar rules. Transcription quality, VAD miss/false-trigger rate and endpoint clipping are separate metrics. For synthesis, evaluate intelligibility, pronunciation, listener preference and, where authorized, reference-speaker similarity on the same prompts. Automatic similarity scores do not replace blinded listening.

Report first partial, end-of-speech-to-final, time to first audible sample, real-time factor, peak memory, cancellation acknowledgment and cost per completed task. Include warm/cold distinction, runtime/model/checkpoint versions, quantization, accelerator, batch/chunk sizes and network region. Published project benchmarks are comparison hypotheses until reproduced on the target hardware. No quality, speed or cost measurements were produced by this review.

Credential-free tests should cover exact request construction, typed unknown JSON rejection, binary size bounds, wrong content type, no audio track, corrupt WAV, output traversal, child timeout/cancellation, missing weights, unavailable accelerator, immutable override constraints, duplicate enrollment and provider verification status. Separate acceptance runs exercise an actual provisioned local model and authorized cloud account. Keep real-device recording/playback tests distinct from fixture media tests. A discoverable backend reports ready only at the level its probe actually verified.
