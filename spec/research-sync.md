# Research source maintenance

[Analysis catalog](analyses/README.md) · [Architecture](architecture.md) · [Verification](verification.md)

The maintenance tasks refresh source evidence and prepare reviewable changes. Fetching a revision, extracting text, and reviewing an architectural claim are separate recorded operations. An unchanged import is a freshness check; a fetched commit is not automatically an analyzed commit.

## Project settings

The versioned `.env` contains non-secret defaults. The ignored `.env.local` overrides them for this checkout. Both files resolve paths relative to their own project directory, independently of the caller's working directory. The portable source inventory is [`git-sources.json`](../git-sources.json), and review status remains in [`spec/analyses/state.json`](analyses/state.json). A fresh checkout needs neither the original parent folder nor its generated shell script. This machine imports parent exports and uses `..` as its Git cache through local settings.

| Setting | Default | Meaning |
|---|---|---|
| `TEAMAGENT_GIT_SOURCES_DIR` | unset | Optional directory containing regenerable `.git-clone` / `.git-sources` import data; unset uses the repository-owned inventory |
| `TEAMAGENT_GIT_CACHE` | `.cache/git` | Categorized repository checkout root |
| `TEAMAGENT_GIT_AUTO_STASH` | `true` | Save tracked/untracked changes before updating, restore afterward and retain the recovery stash |
| `TEAMAGENT_GIT_OUTDATED_THRESHOLD` | `4m` | Calendar months without an upstream commit; `d` means days |
| `TEAMAGENT_GIT_OUTDATED_PREFIX` | `xx-<YYMM>-` | Outdated directory prefix; date comes from last upstream commit |
| `TEAMAGENT_GIT_REMOVED_PREFIX` | `zz-<YYMM>-` | Operational removed/inaccessible directory prefix |
| `TEAMAGENT_GIT_BACKUP_ACCOUNT` | unset/current account | Authenticated GitHub user or explicitly selected organization |
| `TEAMAGENT_REPOMIX_CACHE` | `.cache/git.repomix` | Optional repository packing benchmark/output cache |
| `TEAMAGENT_TEXT_CACHE` | `.cache/text` | Versioned text import store and exported Markdown/images |

Settings use literal single-line `KEY=value` assignments, optionally quoted, and whole-line `#` comments. No interpolation, shell evaluation, executable dotenv, ancestor discovery or ambient environment override is supported. Unknown Teamagent keys and duplicate keys in one file fail. Keep credentials out of these files; private Git operations use the existing Git credential helper. The application's explicit C12 server configuration remains a separate contract.

## Tasks

Use the pinned Bun/Aube runtime described in [the stack](architecture/stack.md). Git maintenance itself uses PowerShell 7 and Git, including the standard HTTP client for private backups; it does not require `fd`, `gh`, Python or a package installation. The executable updater belongs to this repository. Parent `.git-clone` exports are input data: their shell headers are ignored, never executed or copied into the updater. They may be regenerated by other tooling without preserving Teamagent code. Ordinary maintenance does not rewrite parent exports or the legacy root `.git-clone` / `.git-sources` files.

```sh
aube run --no-install sources:sync
aube run --no-install repos:sync
aube run --no-install repos:status
aube run --no-install analysis:sync
aube run --no-install resources:sync
aube run --no-install research:sync
```

`sources:sync` imports the configured external exports into `git-sources.json` and records a local import receipt. It does not publish shell-script copies. `repos:sync` consumes the owned JSON inventory, without rereading external exports. `research:sync` runs those stages, analysis evidence preparation, and text-resource synchronization in that order. It continues independent evidence stages after a partially failed repository sync and exits nonzero for incomplete execution. A failed list publication stops dependent updates. `--root`, `--limit`, `--category`, `--repository`, `--no-auto-stash`, `--use-primary-branch`, `--timeout-seconds` and `--concurrency` are available through the launcher; use each underlying script's help for its more specific options. A limit is explicitly partial coverage, never a full scan.

The standalone Git entry point is `pwsh -NoProfile -File app/research/git-sync.ps1 -Action sync -ProjectRoot .`. Actions are `lists`, `sync`, and `status`. Run `status` to detect staged, unstaged, untracked and submodule changes without merging them. The output manifests are `.cache/research/git-state.json` and `.cache/research/git-sync.json`; their local paths are project-relative. These caches are machine state, not portable source citations.

## Repository lifecycle

The owned `git-sources.json` has schema version 1 and a sorted `repositories` array of `{category, name, url}` records. It contains no absolute paths, credentials, cache locations or review claims. Only the 19 requested AI source categories are selected. During an explicit source import, literal clone declarations provide category/name/URL mappings; clone scripts are never evaluated. A nonempty auxiliary `.git-sources` list must contain the selected declared URLs. A missing or empty auxiliary export is reported explicitly while complete validated clone declarations remain usable. Malformed declarations, unsafe paths, URL mismatches and duplicate identities fail before publication. The previous owned configuration survives a rejected import. The import never edits parent exports. Cache containment, aliases, reparse points, conflicting destinations and expected origins are checked before mutation. Completed staged clones and lifecycle prefix changes use an atomic native directory rename within the same parent. Every attempt rechecks cache containment and refuses an existing destination; the updater never merges, overwrites or deletes that destination. Only sharing or access errors are retried, for at most four attempts with bounded delays. Failed publication retains the staging directory and reports its relative path. The manifest records the operation stage, relative source/destination, attempt count and sanitized exception type/HResult/native error code; unrelated I/O failures are reported immediately.

Existing checkouts are fetched without pruning away retained evidence. By default, tracked and untracked changes are stashed before a fast-forward update, then reapplied by exact stash object ID. Ignored files are not stashed or overwritten. Recovery stashes remain available after restoration; a conflict is an explicit partial result with the stash retained. Set `TEAMAGENT_GIT_AUTO_STASH=false` or pass `--no-auto-stash` to leave dirty checkouts untouched.

A detached checkout is preserved at its exact commit on a dedicated recovery branch before switching to the remote primary branch. Choosing a nearest commit could discard distinct detached work, so no proximity heuristic or replay is used. A local branch with no upstream, or with a configured origin upstream that is now missing, is left alone by default; explicitly passing `--use-primary-branch` preserves both that branch and an exact recovery reference before using the same primary-branch recovery path. For a missing upstream, the exact origin reference must be verified absent, and the reachable remote default determines the target even if cached origin/HEAD is stale. The original branch and its tracking configuration remain intact. Tracking another remote stays blocked.

Existing primary branches must track the expected upstream and fast-forward safely. Divergence, blocked checkout and stash-restore conflicts retain recovery references and require review. The updater does not hard-reset, clean, force checkout, or delete a source repository.

Outdated prefixes follow last-upstream-commit age and are removed if activity resumes. The `zz` prefix is an operational inaccessible classification, not proof that GitHub deleted a project: a private repository or revoked access can also return 404. Repeated authenticated not-found observations must span at least 24 hours; ordinary transport failures, rate limiting and authentication errors remain unavailable. Each subsequent sync rechecks these records, including temporarily banned sources. It does not forget them when a source disappears from the list.

Private backup requires a retained checkout and an authenticated account. A deterministic destination name includes a source identity hash. Creation requests `private=true`; an existing destination must match a recorded backup identity, owner and privacy status before pushes. Failed creation, insufficient permissions, shallow history and missing retained material are recorded rather than described as complete backups. No public publishing or origin rewrite is involved.

A directory rename is not a source identity change. Analysis reconciliation uses canonical origin and full analyzed SHA ancestry, preserves aliases, refuses ambiguous matches, and explicitly reports unavailable/shallow history. A shared ancestor alone does not establish that an arbitrary fork is an upstream rename; changed-origin cases need reviewed identity mapping. Reports retain their established links and original commit evidence.

## Analysis review and promotion

[The compact repository index](analyses/repositories.md) records analyzed and observed revisions independently. Each repository has its original report plus a bounded change packet. Commit history and changed paths are collected from the analyzed commit to the observed revision, with truncation and history-rewrite states explicit. Start from changed entry points, protocols, manifests and tests; use targeted source expansion before whole-repository packing.

Update an affected report with pinned upstream links and a scoped assessment, then explicitly acknowledge that review:

```sh
bun app/research/analysis-sync.ts --root . --write --review <id> --sha <full-sha> --reason "Reviewed changed adapter and tests"
```

The acknowledged SHA must be the observed revision, the report must cite that source/revision, and changed source requires an updated report body. This records an editorial review; it is not an automated correctness proof. Archive retains the report and provenance. An unavailable repository alone does not authorize archival. Update all related direction documents when a recommendation changes, retaining the reason in [the architecture changelog](CHANGELOG.md) and the repository analysis changelog.

## Text resources and legacy material

Root `.urls.md.conf` and `.urls.pdf.conf` retain the `filename URL` lists. Existing entries now default to **static**: capture a resource once, then preserve that exact successful version. A repeat sync performs local checksum and manifest checks without network access, conversion, export rewriting or authentication. A source that has never been successfully captured may retry its initial import. Local validation binds the export to the exact configured URL, including private query parameters, and checks aggregate and per-file hashes; public reports still omit those query values. A missing or corrupt previously captured snapshot fails explicitly; it does not turn back into a new network import. A successful capture whose export failed still retains its source/version identity, so the next static run requires local restoration rather than another fetch.

Each alias can group up to 16 explicitly chosen URLs in their configured order. Append options immediately after the URL they govern:

```text
article.md https://example.com/article
living-guide.md https://example.com/guide refresh=true
known-date.md https://example.com/post published=2026-10-27
thread.md https://x.com/user/status/123 published=2026-10-27T10:00:00Z https://x.com/user/status/124 refresh=true
```

`refresh=true` explicitly enables remote updates for that URL; `refresh=false` is the default. The optional `published=` value is a user-supplied assertion, separately labeled in the report. Duplicate or invalid options fail instead of being guessed. Filename dates are not source metadata. A group does not implicitly refresh all its URLs, discover a complete thread or substitute another source. Adding or renaming an alias reuses an unambiguous previously captured pin for the exact full URL, including query parameters. Conflicting prior pins block a new static alias until explicitly refreshed or resolved; matching query-redacted display URLs alone never establishes identity.

Run `bun app/research/text-sync.ts --root .`, with optional `--limit N`, `--timeout-ms N` and `--cache path`. Two workers bound initial/refresh imports and conversion. The output separately counts importer calls and locally pinned sources; processing a static source is not a fresh download. Both cache and report directories refuse concurrent writers.

Source state v2 migrates v1 records without replacing their pinned versions. `firstCapturedAt` comes from the retained memory source's original creation timestamp. `sourcePublishedAt` is separate and may come from an explicit list assertion, publisher HTML `article:published_time`/`datePublished`, Article-family JSON-LD `datePublished`, or the exact requested official X post's `created_at`. Evidence type and field are retained; these are publisher/API assertions, not independent proof. Invalid, conflicting or absent metadata stays unknown. A date-only value preserves day precision. HTTP Last-Modified, filesystem timestamps and dates embedded in filenames never become publication dates. Existing recorded dates survive refresh failures; conflicting later metadata is disclosed rather than silently replacing the recorded date.

For explicitly refreshed HTTP sources, available ETag/Last-Modified validators are bound to the exact retained resource URL. A 304 may reuse only checksum-verified original bytes. HTML-linked assets are checked independently; a stable parent response does not prove unchanged images. Source hashes remain the content-version check when validators are absent. The current [source memory](memory-imports.md) contract retains original bytes, immutable versions, checksums and conversion provenance. Reports contain creation/capture dates, pinned versions and local validation times, separately from the last remote attempt.

The report ledger under [text analyses](analyses/texts/README.md) is portable, but `.cache/text` is private machine storage. If a new machine lacks the private ledger, the report ledger still preserves existing pins and prevents silent network replacement. Transfer/back up the corresponding cache or explicit memory exports when moving the static corpus. Missing files are reported; legacy originals under `data/research/texts` are not silently substituted. Login walls, access failures, unsupported bodies and PDF viewer pages remain explicit incomplete outcomes. A previous failed remote check does not prevent local use of an intact pinned snapshot, and local validation does not claim remote freshness.

Initial imports and explicitly marked refreshes fetch the original public URLs without a social login. Captured static resources never use that network path. Optional `--x-api` explicitly enables the [official X post lookup API](https://docs.x.com/x-api/posts/lookup/introduction) using `X_BEARER_TOKEN` from the process environment. It is never enabled automatically and may use paid API access. Passing `--x-api` does not override a captured source's static policy; it affects initial/refresh work only. The adapter validates numeric post identity, retains the original JSON and available `edit_history_tweet_ids`, records `created_at` when valid, prefers long-form `note_tweet.text`, and can capture up to four public image assets from `pbs.twimg.com`, with separate size and time limits. The bearer token is only sent to `api.x.com`; redirects and credential forwarding are forbidden. Multiple chosen post URLs can share an alias, but conversation ID is not a claim of complete replies, quotes or edit history. The requested post ID remains fixed: returned edit-history identifiers are version evidence, not authority to fetch a different post automatically. The official [X field dictionary](https://docs.x.com/x-api/fundamentals/data-dictionary) was rechecked for these fields on 2026-10-27; no live authenticated API test was performed.

The current [X field dictionary](https://docs.x.com/x-api/fundamentals/data-dictionary) describes an `article` object without a stable body schema. Unknown article objects are preserved in original JSON and marked unsupported for body extraction. Standalone article URLs cannot be inferred as post IDs. Video media is not downloaded; available preview images may be retained with an explicit warning. An authenticated live run requires a usable token and account access; fixture success does not prove live permissions or current article compatibility.

`usable-text` is a coarse extraction check: at least 100 web/PDF Markdown characters, no detected access shell, no parser warnings and the expected PDF media type. It does not establish complete or accurate extraction. Short API-validated posts use their known post identity instead of the web-page length threshold and remain partial for unverified thread/article coverage. Image counts do not prove visual fidelity, OCR accuracy or completeness. Public reports strip URL query parameters; private export manifests retain exact locators.

Original resource documents and images are preserved in [data/research/texts](../data/research/texts/). Earlier generated reports and retired helper scripts remain in [the legacy archive](archive/legacy-research/README.md), with a SHA-256 migration manifest and explicit evidence limitations. Their presence is not a current source review. The old helpers depended on untracked machine commands and do not drive the new tasks.
